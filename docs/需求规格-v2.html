0. 目标与范围

目标：在一台 Mac 上管理多套相互隔离的浏览器环境。使用者手动打开环境、手动访问页面、手动填写注册信息。工具只负责三件事：

  1. 隔离：每个环境的数据、设备指纹、网络出口互不相通。
  2. 网络安全：每个环境只走自己绑定的代理，代理失效即断网。
  3. 检测：核对每个环境实际呈现的指纹和网络特征是否符合配置、是否存在泄露、环境之间是否可被关联。
不在范围内（明确不做）
  • 自动注册、自动填表、批量操作、脚本控制页面。
  • 验证码识别或绕过、短信接码对接。
  • 模拟鼠标轨迹、操作节奏等行为特征。
使用者需自行遵守所访问平台的服务条款。
关于“隐藏指纹”
  • 禁用或清空指纹本身就是异常特征。本项目的做法是给每个环境一套像真机、前后自洽、长期稳定的值。
  • 验收以本地检测页和公开检测页的结果为准，不承诺任何检测方案都无法识别。
  • 指纹差异由 fingerprint-chromium 的种子机制实现（Canvas、音频、WebGL 图像等）。按 D23/D24 的选择，CPU 核数取模板值、显卡显示本机真机型号，所以用同一个模板的环境这两项会相同，差异来自种子项和不同模板（见第 8.4 节）。

1. 核心规则

  • 代理一律带用户名密码认证，支持 socks5h 和 http。同一环境两种都配置时优先 socks5h。
  • 代理失效时该环境断网，代码中不存在直连路径。
  • 不安装任何浏览器插件；日常使用中不开启调试协议（CDP）端口。
  • 每个环境的全部信息（账号、代理及密码、指纹配置、浏览器数据）保存在一起，在管理页面可查看、可编辑。
  • 所有功能以“积木”形式加入，每块可单独开关、单独验证。

3. 整体架构

4. 积木结构

核心层只负责环境的增删改查、启动关闭和加锁，不包含任何具体特征。每项功能都是一块积木，统一实现以下接口：

方法作用
Name()积木名，对应 env.json 中 modules 的键
Validate(env)启动前检查：本积木配置是否合法、是否与其他积木矛盾（如 UA 写 Windows 而模板是 Mac）
Apply(env)输出启动参数、进程环境变量、需写入数据目录的文件
Verify(env, 读取结果)启动后核对实际值，返回通过 / 失败及原因
enabled在每个环境的配置里单独开关；关闭即保持浏览器原生行为

5. 网络积木

5.1 本地中转

  • 中转只监听 127.0.0.1；每个打开的环境分配一个独立端口，默认端口范围 20001–20999。
  • 上游类型：socks5h、http，都必须带用户名密码。同一环境两种都配置时优先 socks5h；socks5h 连接失败不会自动切换到 http（避免出口 IP 变化），需在管理页面手动切换。
  • 域名原样转发给上游解析，中转进程内不做任何 DNS 查询。
  • 上游连接失败、认证失败、超时：直接断开浏览器侧连接，记录日志并在管理页面提示。代码中不实现直连分支。
  • 运行中不可更换上游；修改代理须关闭环境后编辑再启动。
  • 浏览器侧只看到 127.0.0.1，拿不到上游地址和密码。
换用 fingerprint-chromium 后，代理认证方案重新评估（2026-11-05）

fingerprint-chromium 官方说明对 --proxy-server 的原文是：“http, socks proxy (password authentication not supported)”。也就是说，换浏览器后两种代理仍然都不能带密码，问题没有消失。逐个比较可选方案：

方案做法结论
A. 本地中转（现方案）浏览器连本机无密码端口，中转带密码连上游保留。socks5h、http 都支持，已实现并有测试
B. 浏览器弹窗输入http 代理返回 407 时，Chromium 弹出账号密码框，手动输入不采用。只对 http 有效，socks5 不弹；每次启动都要输；还会被记住在浏览器数据里
C. 调试协议自动填开 CDP 端口，用 Fetch.authRequired 自动回填密码不采用。只对 http 有效；违反“不开调试端口”（第 1 节），调试端口本身可被检测
D. 浏览器插件插件里写 onAuthRequired不采用。违反 D5“不装插件”
E. 改内核源码在 fingerprint-chromium 补丁上再加认证不采用。要回到自编译（约 100GB 磁盘、数小时），升级时还要重打补丁

另外，中转不只是为了认证。本机与内网地址拦截（5.2）、测试模式放行、出口 IP 复查与一键断网、代理挂掉不直连，都依赖中转。即使将来浏览器支持了代理密码，中转仍然要保留。

可以优化的地方（不改变方案）：中转与上游之间的握手只在“新建连接”时发生，浏览器会复用连接，实际开销很小，暂不需要连接池；http 上游的 CONNECT 已带 Basic 认证，明文 http 网站也走 CONNECT 隧道，代理看不到也改不了请求头。

5.3 出口校验

启动时（浏览器启动之前执行）：

  1. 经中转请求公共 IP 回显服务，取实际出口 IP（服务列表见下方“回显服务”）。
  2. 实际出口 IP 必须等于 env.json 中录入的 exit_ip（默认填代理地址，出口与入口不同时手动修改）。
  3. 实际出口 IP 必须不等于本机真实 IP（本机 IP 在主程序启动时直连获取一次，仅主程序使用）。
  4. 明文 http 回显检查：出现 Via / X-Forwarded-For / Forwarded / 本机真实 IP → 标记代理不合格。
  5. 以上任一不满足 → 不启动，提示原因。不做跨环境查重。

运行中（定时复查）：

  • 每个运行中的环境独立复查，间隔默认在 1–10 秒内随机；设置中可改为固定秒数或其他随机范围（最小 1 秒）。
  • 出口 IP 变化、或等于本机 IP → 立即断开该环境网络，管理页面标红并记录日志。
  • 复查请求失败的计数规则：某个回显服务失败 → 立即换下一个服务重试，不计入失败次数；列表中全部服务都失败才算一次失败，连续 3 次失败则断网。出口 IP 变化不等待，立即断网。
  • 流量估算：每次约 1KB，平均 5 秒一次时单环境约 17MB/天。

回显服务：

  • 使用公共服务轮换，不自建服务器。默认列表：Cloudflare /cdn-cgi/trace、api.ipify.org、icanhazip.com、ifconfig.me；列表存于 settings.json，可增删。
  • 每次复查按顺序轮换起点，分散请求压力。
  • 已知风险（使用者已接受）：高频请求可能被公共服务限流或封禁；若实测频繁失败，调大复查间隔。
  • 明文 http 请求头检查使用支持 http 的回显服务（如 http://httpbin.org/headers），只在启动时和“测试代理”时执行，不参与定时复查。
  • WebRTC 泄露检查使用公共 STUN 服务器（如 stun.l.google.com:19302），在检测页中执行。

6. 多环境并行

同时打开多个环境、各挂各的代理，可以实现，这是本地中转的设计初衷。

问题设计
能同时开几个中转不设上限，Go 处理上百个并发连接无压力。实际上限取决于 Mac 内存（每个 Chromium 约 300MB–1GB）。默认同时打开超过 10 个时在页面给出内存提示，不强制拦截。
会不会串号端口与上游的映射在启动时固定写入，运行中只读，不可修改。中转按“本地监听端口”查映射，不看请求内容。
一个代理挂了只影响对应环境，该环境断网并在页面标红；其他环境不受影响。
端口回收环境关闭或进程崩溃时释放端口；释放后有 60 秒冷却期，冷却期内不分配给任何环境（端口号不参与指纹）。
同一环境开两次环境锁禁止。崩溃后残留的锁通过检测进程是否存活自动清除。
主程序崩溃后的孤儿浏览器见下方 6.1。

6.1 主程序崩溃后的孤儿浏览器（防串号）

风险：主程序异常退出时，中转随之消失，但浏览器进程可能还活着，并持续尝试连原来的 127.0.0.1:端口。如果这个端口随后被分配给另一个环境的中转，孤儿浏览器的请求就会走到别人的代理上，等于两个账号共用一个出口。

措施做法
锁文件记录浏览器 PIDenv.lock 两行：第一行主程序 PID，第二行浏览器 PID（浏览器启动后立即写入）。
判断主程序是否真的活着PID 存在且进程名为 envbrowser 才算存活，防止 PID 被系统复用后环境永远打不开。
加锁时清理主程序已死、锁里的浏览器 PID 还活着，且其命令行确实带本环境的 --user-data-dir → 先结束它（SIGTERM，5 秒后 SIGKILL），再加锁。命令行对不上的进程不动，防止误杀。
启动时全面清理管理页面启动时、以及每次打开环境、分配端口之前，扫描所有带 --user-data-dir=<数据根目录>/env-*/browser 且所属环境没有存活主程序的浏览器主进程，全部结束。清理失败则不启动该环境。
端口冷却中转端口释放后 60 秒内不再分配，给孤儿浏览器留出被清理的时间窗；范围内只剩冷却中的端口时拒绝启动，不复用。

8.1 一致性规则（Validate 统一检查）

  • 系统、UA、Client Hints、navigator.platform、字体集、WebGL 显卡信息必须指向同一类真实设备。fingerprint-chromium 只伪装成 macOS（--fingerprint-platform=macos），模板也只采集 Mac。
  • CPU 核数等于模板值；显卡显示本机真机型号。模板芯片与本机不一致时（例如模板是 M4、本机是 M2），核数与显卡会对不上，新建环境时提示。
  • 时区、语言与出口 IP 所在地一致（不一致时提示，不强制）。
  • 屏幕尺寸、像素比显示本机真机值；窗口尺寸不得超过本机屏幕。
  • 所有带随机性的项由环境种子决定，种子写入 env.json，同一环境每次结果完全一致（实测同一种子两次启动 Canvas、音频哈希相同）。
  • 主页面、iframe、Worker、Service Worker 读到的值必须相同。

8.3 积木开关与参数的对应

  • env.json 的 modules 里每一项开关，由启动器翻译成对应参数：关闭 canvas → 追加 canvas 到 --disable-spoofing，以此类推。
  • fingerprint 总开关关闭时不传 --fingerprint，浏览器按原生行为运行（仅用于对照排查）。
  • 启动器只生成参数，不改浏览器文件；更换浏览器版本只需改设置里的路径和版本号。
  • 升级 fingerprint-chromium 版本前，必须先用检测页跑一遍全部积木，确认参数仍然有效，再切换。

模板种子
是什么一款真实 Mac 机型的公开规格（系统版本、CPU 核数）某个环境专属的最终指纹 = 模板 + 种子扰动
来源按 Apple 官网技术规格整理，内置于 templates/presets.json，不需要采集新建环境时程序自动生成，使用者无需操作
可变性只读；可在管理页启用 / 停用、手动新增生成后与环境永久绑定；可手动“重新生成”
数量当前 4 套，不设上限每个环境一个，不与其他环境共用

生成规则：

  1. 新建环境时，从已启用的模板中轮换选取：优先选被使用次数最少的模板，次数相同时随机。
  2. 以下项取模板值：系统版本（--fingerprint-platform-version）、CPU 核数（--fingerprint-hardware-concurrency）。显卡型号、屏幕、字体列表、媒体设备、语音列表显示本机真机值。
  3. 以下项由种子生成差异：fingerprint 种子整数（程序随机生成，1 到 231−1，所有环境间不重复），由它决定 Canvas、音频、WebGL 图像、内存、ClientRects 等；窗口尺寸（在本机屏幕范围内取常见值）。
  4. 生成的种子写入该环境的 env.json，不同环境的种子不可相同。
  5. 新建环境时检查本机芯片：不是 M2 时提示“模板与本机芯片不一致”。

模板管理页面：模板列表、每个模板被几个环境使用、启用 / 停用（停用后不再被新环境选中，已绑定环境不受影响）、手动新增、删除（有环境在用时禁止删除）。

9. 检测积木

只在测试和验收时使用，日常使用不需要；实施阶段 2 开发。阶段 1 验证时已有一个简易版 tools/fpcheck/（单页 + 无头采集脚本），阶段 2 在此基础上扩充。

9.1 部署与访问

  • 检测页由主程序在本机提供，单独端口，默认127.0.0.1:9000；不与管理页面（8800）共用端口。
  • 环境浏览器访问检测页时，请求同样经过中转（--proxy-bypass-list=<-loopback>）。
  • 测试模式：管理页面上的全局开关，默认关闭。
    • 关闭时：中转拒绝一切本机和内网地址，检测页无法访问。
    • 开启时：中转只放行检测页这一个地址和端口，其他本机端口、内网地址仍然拒绝。
    • 开启期间管理页面顶部持续显示提醒；测试结束后手动关闭。

9.2 检测内容

  • 在主页面、iframe、Worker、Service Worker 中分别读取全部指纹项。
  • 报告每行：检测项 / 配置目标值 / 实际读取值 / 读取位置 / 是否一致。
  • 本机检测页能测：时区、语言、UA、屏幕、Canvas、WebGL、音频、字体、多位置一致性、WebRTC 候选地址（借助公共 STUN）、本机端口扫描测试（验证第 5.2 节本机隔离生效）。
  • 本机检测页测不准（未经代理出网）：出口 IP、代理是否篡改请求头 —— 改由中转在后台用公共回显服务检查（第 5.3 节）。
  • 跨环境比对：出口 IP 与各环境录入值一致；Canvas 哈希任意两个环境互不相同（阶段 2 起检查）；音频哈希重复只提示（只有 7 档，见第 13 节）。
  • 稳定性：同一环境重启 3 次，全部结果一致。
  • 报告保存在该环境目录的 reports/ 下，按时间命名，可在管理页面查看历史。

11. 管理页面

主程序启动后，在本机浏览器打开 http://127.0.0.1:8800/?token=…（默认端口，只监听本机）。

访问保护（审核第 11 条）：

  • 主程序每次启动生成一个随机访问令牌，并自动用带令牌的链接打开管理页面；首次访问后令牌存入 Cookie（HttpOnly、SameSite=Strict）。
  • 所有页面和接口请求必须带有效令牌，否则返回 403。
  • 校验请求头 Host：只接受 127.0.0.1:8800 和 localhost:8800，防止 DNS 重绑定攻击。
  • 修改类接口（新建、编辑、删除、启动、关闭）只接受 POST，并校验 Origin 为本页面。
  • 环境浏览器本身无法访问 8800（第 5.2 节本机隔离），测试模式也不放行此端口。
页面功能
环境列表搜索（名称、账号、备注、代理地址）；显示状态（未打开 / 运行中 / 代理异常）、出口 IP、最近检测结果；启动、关闭、检测按钮
新建 / 编辑环境一个页面填完全部信息：账号与登录密码、代理（类型、地址、端口、用户名、密码可见可改、指定出口 IP）、时区（默认东京）、语言、积木开关。模板与种子自动分配，页面只显示结果，并提供“重新生成种子”按钮。“测试代理”按钮：认证 + 出口 IP + 请求头检查。“按出口 IP 自动匹配时区”按钮
模板管理列出内置模板（机型、芯片、核数、系统版本、来源链接）及使用次数；启用 / 停用；可手动新增一条（填系统版本与核数）
环境详情完整配置、本次运行的本地端口、检测报告历史、运行日志
设置数据根目录、浏览器（fingerprint-chromium）路径与版本、端口范围、内存提示阈值、测试模式开关
  • 运行中的环境，代理和指纹字段只读；关闭后才可编辑。
  • 删除环境：移到废纸篓（整个目录），需二次确认。
  • 复制环境：复制账号、代理以外的配置，重新生成种子，浏览器数据不复制。

12.1 “零直连”与“本机无 DNS”的实测方法（阶段 1.5 用）

判断标准：浏览器的所有进程只允许连 127.0.0.1；对外的连接只能由主程序发起，且目标只能是该环境的上游代理。用 macOS 自带工具即可，不需要装抓包软件。

  1. 找出这个环境的全部浏览器进程（Chromium 是多进程，网络请求由其中的网络服务进程发出）：
    pgrep -f 'user-data-dir=.*env-0001/browser'
  2. 看浏览器进程连了哪里，正常只应出现 127.0.0.1:2000x：
    lsof -nP -iTCP -iUDP -a -p $(pgrep -d, -f 'user-data-dir=.*env-0001/browser')
    边浏览网页边每秒执行一次，出现任何非 127.0.0.1 的地址即为直连。
  3. 看主程序连了哪里，正常只应出现上游代理地址：
    lsof -nP -iTCP -a -p $(pgrep -x envbrowser)
  4. 抓本机 DNS 查询（需要管理员密码）：
    sudo tcpdump -i any -n 'port 53 or port 5353 or port 853'
    打开环境、浏览几个网站，期间不应出现由浏览器访问的网站域名。主程序启动时查一次本机 IP、以及上游代理若填的是域名，会各产生一次查询，属正常。
  5. 断上游测试：浏览中在代理后台停用该代理（或临时改错密码），确认页面立即打不开，同时第 2 步仍然没有非 127.0.0.1 的连接。
  6. WebRTC / UDP：第 2 步结果中不应出现任何 UDP 外连；在 browserleaks 的 WebRTC 页确认看不到本机和内网 IP。

以上步骤已整理成 scripts/field-test.sh（调用 envbrowser fieldtest）：隐藏输入代理；第 2、3 步每秒用 lsof 采样，只绑定未连接的 UDP（发布前冒烟偶见网络服务进程有 2 个）单独列出并用 nettop 读发出字节数，0 字节只提示不算失败；另用 pktap 按进程抓包，浏览器进程向本机以外发出任何报文即判未通过，这是第 3 步的最终判定，报告只写条数和进程类型，不写目标地址；第 4 步后台 tcpdump，只判断浏览器访问的站点（example.com、neverssl.com）有没有出现在 DNS 查询里，报告不记录其他查询；第 5 步由中转模拟出口异常并确认连接全部切断；另加检测页全部项目、两个环境 Cookie 隔离、错误密码不启动、结束无残留进程。报告 field-report.txt 中代理地址、用户名、密码、出口 IP、本机公网 IP 均已打码。
