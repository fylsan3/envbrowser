# 浏览器项目：需求与设计草案

状态：需求讨论阶段，尚未开始编码。技术栈未确定。

## 已确认需求
- 自用，第一版运行于 macOS。
- 用于测试自有服务的浏览器指纹识别。
- 账号属于自有服务；宣传仅面向明确同意订阅的用户。
- 环境按需创建，不固定数量，不预设数量上限。
- 每次仅打开少量环境，其余环境保存在硬盘上。
- 每个环境独立保存 Cookie、登录状态、缓存及配置。
- 每个环境固定绑定各自的 SOCKS 代理。
- 代理失效时必须阻断请求，禁止回退直连。
- 浏览器测试特征可配置、可重复，并验证实际读取结果。

## 设计方向
- 一套共享 Chromium 程序，多份独立环境数据。
- 管理界面负责环境创建、编辑、启动、关闭及检索。
- 控制服务负责配置、进程生命周期和环境锁。
- 代理安全模块负责认证、远端 DNS 和断网保护。
- 检测模块对比配置目标、网页读取值和自有服务识别结果。
- 普通设置能完成的功能不改内核；必要时评估 Chromium 补丁。
- 保留沙箱、证书校验及安全更新能力。

## 实施顺序
1. 明确指纹测试项、实现方式与验收标准。
2. 使用两个样本环境验证隔离、稳定性和代理阻断。
3. 按需实现可开关、可测试的浏览器特征修改。
4. 完成动态环境管理界面及识别结果对比。
5. 完成安全验证，再确认打包和发布。

## 重要约束
- 不承诺修改后无法被识别或关联。
- 本地代理中转不等于杜绝直连，需网络约束和实际验证。
- 时区、语言、窗口、UA 等设置机制需分别验证。
- 测试账号的真实发送权限应由自有服务端禁止。
- 未经用户确认，不确定技术栈，不修改配置，不开始编码。
