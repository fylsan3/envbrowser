更新：2026-11-05 17:10（第 3 版：本机隔离、检测页与测试模式、管理页面令牌、公共回显服务轮换） · 运行平台：macOS · 基于《需求与设计草案.md》整理（草案原文未改动）· 标 默认 的条目为代定默认值，可直接修改

0. 目标与范围

目标：在一台 Mac 上管理多套相互隔离的浏览器环境。使用者手动打开环境、手动访问页面、手动填写注册信息。工具只负责三件事：

  1. 隔离：每个环境的数据、设备指纹、网络出口互不相通。
  2. 网络安全：每个环境只走自己绑定的代理，代理失效即断网。
  3. 检测：核对每个环境实际呈现的指纹和网络特征是否符合配置、是否存在泄露、环境之间是否可被关联。
不在范围内（明确不做）
  • 自动注册、自动填表、批量操作、脚本控制页面。
  • 验证码识别或绕过、短信接码对接。
  • 模拟鼠标轨迹、操作节奏等行为特征。
使用者需自行遵守所访问平台的服务条款。
关于“隐藏指纹”
  • 禁用或清空指纹本身就是异常特征。本项目的做法是给每个环境一套像真机、前后自洽、长期稳定的值。
  • 验收以本地检测页和公开检测页的结果为准，不承诺任何检测方案都无法识别。
  • 在同一台 Mac 上只用启动参数时，所有环境的 Canvas、WebGL、音频指纹相同。要让每个环境指纹不同，必须完成第二阶段的内核积木。

1. 核心规则

  • 代理一律带用户名密码认证，支持 socks5h 和 http。同一环境两种都配置时优先 socks5h。
  • 代理失效时该环境断网，代码中不存在直连路径。
  • 不安装任何浏览器插件；日常使用中不开启调试协议（CDP）端口。
  • 每个环境的全部信息（账号、代理及密码、指纹配置、浏览器数据）保存在一起，在管理页面可查看、可编辑。
  • 所有功能以“积木”形式加入，每块可单独开关、单独验证。

4. 积木结构

核心层只负责环境的增删改查、启动关闭和加锁，不包含任何具体特征。每项功能都是一块积木，统一实现以下接口：

方法作用
Name()积木名，对应 env.json 中 modules 的键
Validate(env)启动前检查：本积木配置是否合法、是否与其他积木矛盾（如 UA 写 Windows 而模板是 Mac）
Apply(env)输出启动参数、进程环境变量、需写入数据目录的文件
Verify(env, 读取结果)启动后核对实际值，返回通过 / 失败及原因
enabled在每个环境的配置里单独开关；关闭即保持浏览器原生行为

5. 网络积木

5.1 本地中转

  • 中转只监听 127.0.0.1；每个打开的环境分配一个独立端口，默认端口范围 20001–20999。
  • 上游类型：socks5h、http，都必须带用户名密码。同一环境两种都配置时优先 socks5h；socks5h 连接失败不会自动切换到 http（避免出口 IP 变化），需在管理页面手动切换。
  • 域名原样转发给上游解析，中转进程内不做任何 DNS 查询。
  • 上游连接失败、认证失败、超时：直接断开浏览器侧连接，记录日志并在管理页面提示。代码中不实现直连分支。
  • 运行中不可更换上游；修改代理须关闭环境后编辑再启动。
  • 浏览器侧只看到 127.0.0.1，拿不到上游地址和密码。

5.2 断网保护（三层）

5.3 出口校验

启动时（浏览器启动之前执行）：

  1. 经中转请求公共 IP 回显服务，取实际出口 IP（服务列表见下方“回显服务”）。
  2. 实际出口 IP 必须等于 env.json 中录入的 exit_ip（默认填代理地址，出口与入口不同时手动修改）。
  3. 实际出口 IP 必须不等于本机真实 IP（本机 IP 在主程序启动时直连获取一次，仅主程序使用）。
  4. 明文 http 回显检查：出现 Via / X-Forwarded-For / Forwarded / 本机真实 IP → 标记代理不合格。
  5. 以上任一不满足 → 不启动，提示原因。不做跨环境查重。

运行中（定时复查）：

  • 每个运行中的环境独立复查，间隔默认在 1–10 秒内随机；设置中可改为固定秒数或其他随机范围（最小 1 秒）。
  • 出口 IP 变化、或等于本机 IP → 立即断开该环境网络，管理页面标红并记录日志。
  • 复查请求失败的计数规则：某个回显服务失败 → 立即换下一个服务重试，不计入失败次数；列表中全部服务都失败才算一次失败，连续 3 次失败则断网。出口 IP 变化不等待，立即断网。
  • 流量估算：每次约 1KB，平均 5 秒一次时单环境约 17MB/天。

回显服务：

  • 使用公共服务轮换，不自建服务器。默认列表：Cloudflare /cdn-cgi/trace、api.ipify.org、icanhazip.com、ifconfig.me；列表存于 settings.json，可增删。
  • 每次复查按顺序轮换起点，分散请求压力。
  • 已知风险（使用者已接受）：高频请求可能被公共服务限流或封禁；若实测频繁失败，调大复查间隔。
  • 明文 http 请求头检查使用支持 http 的回显服务（如 http://httpbin.org/headers），只在启动时和“测试代理”时执行，不参与定时复查。
  • WebRTC 泄露检查使用公共 STUN 服务器（如 stun.l.google.com:19302），在检测页中执行。

6. 多环境并行

同时打开多个环境、各挂各的代理，可以实现，这是本地中转的设计初衷。

问题设计
能同时开几个中转不设上限，Go 处理上百个并发连接无压力。实际上限取决于 Mac 内存（每个 Chromium 约 300MB–1GB）。默认同时打开超过 10 个时在页面给出内存提示，不强制拦截。
会不会串号端口与上游的映射在启动时固定写入，运行中只读，不可修改。中转按“本地监听端口”查映射，不看请求内容。
一个代理挂了只影响对应环境，该环境断网并在页面标红；其他环境不受影响。
端口回收环境关闭或进程崩溃时释放端口；下次启动重新分配（端口号不参与指纹）。
同一环境开两次环境锁禁止。崩溃后残留的锁通过检测进程是否存活自动清除。

8. 指纹积木

8.1 一致性规则（Validate 统一检查）

  • 系统、UA、Client Hints、navigator.platform、字体集、WebGL 显卡信息必须指向同一类真实设备。
  • 时区、语言与出口 IP 所在地一致（不一致时提示，不强制）。
  • 屏幕尺寸、可用区域、像素比必须是设备模板里的真实组合。
  • 所有带随机性的项共用一个环境种子，种子写入 env.json，同一环境每次结果完全一致。
  • 主页面、iframe、Worker、Service Worker 读到的值必须相同。

8.3 内核补丁规范（阶段二）

  • 每块积木一个独立补丁文件，只读取 --fingerprint-profile=<路径> 指向的配置。
  • 配置里没有某项 = 该项保持原生行为，积木可单独关闭。
  • 修改全部在 C++ 层，JS 看到的仍是原生函数。
  • 保留沙箱与证书校验，不关闭任何安全特性。
  • 默认每个 Chromium 稳定大版本发布后 2 周内完成补丁合并、编译和全量回归。

8.4 模板与种子

模板种子
是什么一台真 Mac 的整套硬件与浏览器参数某个环境专属的最终指纹 = 模板 + 轻微改动
来源使用者用采集脚本在真 Mac 上采集，2–3 套新建环境时程序自动生成，使用者无需操作
可变性只读生成后与环境永久绑定；可手动“重新生成”
数量不设上限每个环境一个，不与其他环境共用

生成规则：

  1. 新建环境时，从已启用的模板中轮换选取：优先选被使用次数最少的模板，次数相同时随机。
  2. 以下项保持模板原值（改了会出现真机不存在的组合）：机型、系统版本、显卡厂商与型号、WebGL 参数与扩展、屏幕分辨率与像素比、CPU 核数、内存、字体列表、语音列表。
  3. 以下项由种子生成差异：Canvas 扰动值、音频扰动值、媒体设备 ID、窗口尺寸（在模板屏幕范围内取常见值）。
  4. 生成的种子写入该环境的 env.json，不同环境的种子不可相同。
  5. 模板的硬件参数要到实施阶段 5（内核积木）才真正生效；阶段一至四网站读到的是本机真实硬件。

模板采集脚本：

  • 提供一个独立的命令行脚本 collect-template（随主程序打包，可单独拷到其他 Mac 上运行）。
  • 运行方式：在要采集的真 Mac 上执行 ./collect-template --name mac-mini-m2。
  • 脚本自动：调用本机已安装的 Chrome 以无头模式打开内置采集页 → 读取全部参数 → 同时读取系统信息（机型、系统版本、芯片、屏幕）→ 输出 mac-mini-m2.template.json。
  • 使用者把输出文件拷回，在管理页面“模板管理 → 导入”，或直接放进 ~/BrowserEnvs/templates/。
  • 导入时校验：格式、必填项、与已有模板是否重复（重复则提示）。
  • 脚本会额外用有界面模式采集一次 WebGL/Canvas 并与无头模式对比，因为无头模式下显卡信息可能与日常使用不同；两者不一致时以有界面结果为准。

模板管理页面：模板列表、每个模板被几个环境使用、启用 / 停用（停用后不再被新环境选中，已绑定环境不受影响）、删除（有环境在用时禁止删除）。

9. 检测积木

只在测试和验收时使用，日常使用不需要；实施阶段 3 再开发。

9.1 部署与访问

  • 检测页由主程序在本机提供，单独端口，默认127.0.0.1:9000；不与管理页面（8800）共用端口。
  • 环境浏览器访问检测页时，请求同样经过中转（--proxy-bypass-list=<-loopback>）。
  • 测试模式：管理页面上的全局开关，默认关闭。
    • 关闭时：中转拒绝一切本机和内网地址，检测页无法访问。
    • 开启时：中转只放行检测页这一个地址和端口，其他本机端口、内网地址仍然拒绝。
    • 开启期间管理页面顶部持续显示提醒；测试结束后手动关闭。

9.2 检测内容

  • 在主页面、iframe、Worker、Service Worker 中分别读取全部指纹项。
  • 报告每行：检测项 / 配置目标值 / 实际读取值 / 读取位置 / 是否一致。
  • 本机检测页能测：时区、语言、UA、屏幕、Canvas、WebGL、音频、字体、多位置一致性、WebRTC 候选地址（借助公共 STUN）、本机端口扫描测试（验证第 5.2 节本机隔离生效）。
  • 本机检测页测不准（未经代理出网）：出口 IP、代理是否篡改请求头 —— 改由中转在后台用公共回显服务检查（第 5.3 节）。
  • 跨环境比对：出口 IP 与各环境录入值一致；指纹哈希互不相同这一项从实施阶段 5（内核积木完成）起才检查，阶段一至四硬件类指纹必然相同。
  • 稳定性：同一环境重启 3 次，全部结果一致。
  • 报告保存在该环境目录的 reports/ 下，按时间命名，可在管理页面查看历史。

11. 管理页面

主程序启动后，在本机浏览器打开 http://127.0.0.1:8800/?token=…（默认端口，只监听本机）。

访问保护（审核第 11 条）：

  • 主程序每次启动生成一个随机访问令牌，并自动用带令牌的链接打开管理页面；首次访问后令牌存入 Cookie（HttpOnly、SameSite=Strict）。
  • 所有页面和接口请求必须带有效令牌，否则返回 403。
  • 校验请求头 Host：只接受 127.0.0.1:8800 和 localhost:8800，防止 DNS 重绑定攻击。
  • 修改类接口（新建、编辑、删除、启动、关闭）只接受 POST，并校验 Origin 为本页面。
  • 环境浏览器本身无法访问 8800（第 5.2 节本机隔离），测试模式也不放行此端口。
页面功能
环境列表搜索（名称、账号、备注、代理地址）；显示状态（未打开 / 运行中 / 代理异常）、出口 IP、最近检测结果；启动、关闭、检测按钮
新建 / 编辑环境一个页面填完全部信息：账号与登录密码、代理（类型、地址、端口、用户名、密码可见可改、指定出口 IP）、时区（默认东京）、语言、积木开关。模板与种子自动分配，页面只显示结果，并提供“重新生成种子”按钮。“测试代理”按钮：认证 + 出口 IP + 请求头检查。“按出口 IP 自动匹配时区”按钮
模板管理导入采集脚本生成的模板文件；列表显示使用次数；启用 / 停用 / 删除
环境详情完整配置、本次运行的本地端口、检测报告历史、运行日志
设置数据根目录、Chromium 路径与版本、端口范围、内存提示阈值
  • 运行中的环境，代理和指纹字段只读；关闭后才可编辑。
  • 删除环境：移到废纸篓（整个目录），需二次确认。
  • 复制环境：复制账号、代理以外的配置，重新生成种子，浏览器数据不复制。

12. 实施顺序与验收

阶段内容验收标准
1核心层 + 网络积木 + 2 个样本环境两个环境 Cookie 互不可见；socks5h 与 http 均能带用户名密码连通；http 上游访问明文 http（80 端口）网站正常（部分 HTTP 代理只允许 CONNECT 443，不通时中转需改用普通转发）；出口 IP 与录入值一致且不等于本机 IP，运行中更换代理出口能在复查间隔内断网；断掉上游后该环境所有页面打不开，抓包确认零直连；WebRTC 检测不到真实 IP 与内网 IP；本机无 DNS 查询
2多环境并行同时打开 5 个环境、各走各的代理，出口 IP 各不相同；任意关掉一个代理只影响对应环境；崩溃后残留锁可自动清除
3阶段一指纹积木 + 检测页时区、语言三处、窗口与配置一致；主页面 / iframe / Worker 一致；重启 3 次结果不变；测试模式关闭时检测页不可访问，开启时只有检测页可访问；本机端口扫描测试中所有端口表现一致
4管理页面新建、编辑、启动、关闭、搜索、检测、复制、删除全部可用；运行中禁止编辑代理与指纹
5自编译 Chromium + 阶段二内核积木每块积木可单独开关；任意两个环境指纹哈希不同；检测页无矛盾项
6安全验证与打包沙箱、证书校验正常；完成签名与公证

13. 风险与已知限制

项说明
代理与账号密码明文存放代理密码、账号登录密码按要求明文保存在 env.json；Cookie 因 --use-mock-keychain 也等同明文。备份、同步网盘、发给他人时会一并带走。建议数据根目录不放在 iCloud 等同步目录下。
出口 IP 复查流量默认 1–10 秒随机复查，单环境约 17MB/天；按流量计费的代理需计入成本。回显服务使用公共服务轮换，可能被限流（已接受）。

已暴露的代理密码x.x.x.x:端口 的用户名密码已在聊天和终端历史中出现，建议在代理后台修改后再录入。

指纹不承诺无法识别阶段一完成时，各环境的硬件类指纹仍相同；阶段二完成后也只保证自洽与差异化，不保证对所有检测方案有效。
跨系统伪装第一版只做 macOS 模板，不支持伪装成 Windows / Android。
行为特征鼠标轨迹、输入节奏等不在本项目范围内。
pf 防火墙需要管理员权限安装规则；首次运行时由使用者手动授权。
